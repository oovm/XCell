# XCell 模板语法修复 - 产品需求文档

## 概述
- **摘要**：修复 XCell 模板引擎中使用错误 Jinja 语法的问题，确保生成的文件不再残留模板语法。
- **目的**：解决模板渲染错误，确保生成的 TypeScript 文件格式正确，不含残留的模板语法。
- **目标用户**：使用 XCell 导出游戏配置表的开发人员。

## 目标
- 修复所有模板文件中的语法错误，从 Jinja 语法转换为正确的 dejavu 语法。
- 确保生成的文件不再包含残留的模板语法。
- 验证修复后的模板能够正确渲染，生成格式正确的 TypeScript 文件。

## 非目标（超出范围）
- 不修改 XCell 的核心功能。
- 不修改模板的整体结构和逻辑。
- 不添加新的功能或特性。

## 背景与上下文
- XCell 是一个策划配表导出工具，使用 dejavu 作为模板引擎。
- dejavu 模板引擎使用 `<% variable %>` 语法输出变量，`<% if condition %>` 语法进行条件判断，`<% loop item in list %>` 语法进行循环。
- 目前的模板文件中存在错误的 Jinja 语法，导致生成的文件残留模板语法。
- 问题出现在 `XCell/examples/galgame/cocos` 目录下的生成文件中，包括 `AchievementsTable.ts`、`AffectionConditionTable.ts`、`AffectionTable.ts`、`CharactersTable.ts`、`ChoicesTable.ts`、`DataTableManager.ts`、`DialoguesTable.ts`、`EndingsTable.ts` 和 `ScenesTable.ts`。

## 功能需求
- **FR-1**：修复所有模板文件中的语法错误，从 Jinja 语法转换为正确的 dejavu 语法。
- **FR-2**：确保模板渲染时能够正确解析所有变量和控制流语句。
- **FR-3**：验证修复后的模板能够生成格式正确的 TypeScript 文件，不含残留的模板语法。

## 非功能需求
- **NFR-1**：修复后的模板应保持与原有模板相同的功能和结构。
- **NFR-2**：修复过程应最小化对现有代码的修改。
- **NFR-3**：修复后的模板应能够在所有支持的平台上正常工作。

## 约束
- **技术**：使用 dejavu 模板引擎，遵循其语法规则。
- **依赖**：依赖 dejavu-engine 和 dejavu-macros 库。

## 假设
- 所有模板文件都使用相同的语法规则。
- 修复后的模板能够与现有的代码生成逻辑兼容。

## 验收标准

### AC-1：模板语法修复
- **给定**：模板文件使用错误的 Jinja 语法。
- **当**：将 Jinja 语法转换为正确的 dejavu 语法。
- **然后**：模板文件能够正确渲染，生成的文件不含残留的模板语法。
- **验证**：`programmatic`
- **注意**：需要检查所有模板文件，确保语法正确。

### AC-2：变量解析正确
- **给定**：模板文件包含变量和控制流语句。
- **当**：渲染模板时。
- **然后**：所有变量和控制流语句都能被正确解析。
- **验证**：`programmatic`
- **注意**：需要确保所有必要的变量都被传递给模板。

### AC-3：生成文件格式正确
- **给定**：使用修复后的模板生成 TypeScript 文件。
- **当**：查看生成的文件。
- **然后**：生成的文件格式正确，不含残留的模板语法。
- **验证**：`human-judgment`
- **注意**：需要检查所有生成的文件，确保格式正确。

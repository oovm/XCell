# XCell 配置格式升级 - 支持多个同一类后端生成

## 概述
- **摘要**：将当前的配置格式从单个后端配置改为支持同一类后端生成多个实例的格式，使用 `[[generator]]` 列表语法。
- **目的**：解决当前配置格式无法为同一类后端（如多个 Unity 项目）生成不同配置的问题，提高配置的灵活性和可扩展性。
- **目标用户**：使用 XCell 工具的游戏开发者和数据工程师。

## 目标
- 支持在配置文件中定义多个同一类型的后端生成器
- 保持向后兼容性，确保现有配置文件仍然可以正常工作
- 提供清晰、直观的配置语法，便于用户理解和使用
- 确保配置解析代码能够正确处理新的配置格式

## 非目标（范围外）
- 不改变现有后端生成器的内部实现逻辑
- 不添加新的后端生成类型
- 不修改生成代码的内容和格式

## 背景与上下文
当前的 XCell 配置格式中，每种后端类型（如 Unity、Cocos）只能定义一个配置实例。这限制了用户在同一项目中为不同的目标（如多个 Unity 项目或不同的部署环境）生成不同配置的能力。

通过将配置格式改为使用 `[[generator]]` 列表语法，可以允许用户为同一类型的后端定义多个生成器实例，每个实例可以有不同的配置参数。

## 功能需求
- **FR-1**：支持在配置文件中使用 `[[generator]]` 列表语法定义多个生成器实例
- **FR-2**：每个生成器实例必须包含 `type` 字段，指定生成器类型（如 unity、cocos 等）
- **FR-3**：每个生成器实例可以包含对应类型的特定配置字段
- **FR-4**：保持向后兼容性，确保现有配置文件仍然可以正常工作

## 非功能需求
- **NFR-1**：配置解析代码应具有良好的错误处理能力，当配置格式错误时提供清晰的错误信息
- **NFR-2**：新的配置格式应保持简洁明了，便于用户理解和维护
- **NFR-3**：配置解析性能不应受到显著影响

## 约束
- **技术**：使用 Rust 语言和 serde 库进行配置解析
- **依赖**：依赖 toml 库解析 TOML 格式的配置文件

## 假设
- 假设用户熟悉 TOML 格式的语法，特别是列表语法
- 假设用户了解不同后端生成器的配置参数

## 验收标准

### AC-1：新配置格式支持多个生成器实例
- **给定**：配置文件中定义了多个同一类型的生成器实例
- **当**：解析配置文件时
- **然后**：所有生成器实例都被正确解析，并且可以独立执行生成任务
- **验证**：`programmatic`

### AC-2：向后兼容性
- **给定**：使用旧格式的配置文件
- **当**：解析配置文件时
- **然后**：配置文件被正确解析，生成器能够正常工作
- **验证**：`programmatic`

### AC-3：配置错误处理
- **给定**：配置文件中存在格式错误
- **当**：解析配置文件时
- **然后**：系统提供清晰的错误信息，指示错误的位置和原因
- **验证**：`programmatic`

# 使用 derive(Template) 重构代码生成 - 产品需求文档

## 概述
- **摘要**：将 Cocos 代码生成器从手动字符串拼接改为使用 dejavu 模板系统和 `derive(Template)` 宏，提高代码的可维护性和可读性。
- **目的**：简化代码生成逻辑，使生成的代码更易于维护和修改，减少手动拼接字符串可能带来的错误。
- **目标用户**：XCell 工具的维护者和开发者。

## 目标
- 使用 dejavu 模板系统重构 Cocos 代码生成器
- 定义合适的模板文件用于生成表类
- 定义合适的模板文件用于生成 DataTableManager
- 保持现有功能不变，确保生成的代码与之前一致

## 非目标（范围外）
- 不修改 Unity 代码生成器
- 不修改其他平台的代码生成器
- 不改变生成的代码的功能

## 背景与上下文
- 当前 Cocos 代码生成器使用手动字符串拼接的方式生成代码
- 项目中已经有 dejavu 模板系统和 `derive(Template)` 宏的使用示例
- 使用模板系统可以提高代码的可维护性

## 功能需求
- **FR-1**：创建 Cocos 表类生成模板
- **FR-2**：创建 Cocos DataTableManager 生成模板
- **FR-3**：重构 Cocos 代码生成器使用模板系统
- **FR-4**：确保生成的代码与之前完全一致

## 非功能需求
- **NFR-1**：保持生成过程的性能
- **NFR-2**：代码应符合 Rust 代码规范
- **NFR-3**：模板文件应易于理解和修改

## 约束
- **技术**：必须使用现有的 dejavu 模板系统
- **依赖**：依赖 dejavu_macros 和 dejavu_types 库

## 假设
- dejavu 模板系统可以正常工作
- 可以创建合适的模板文件来满足需求

## 验收标准

### AC-1：表类模板创建
- **给定**：需要生成的 Cocos 表类
- **当**：使用模板系统生成代码
- **然后**：生成的代码与手动拼接的代码完全一致
- **验证**：`programmatic`

### AC-2：DataTableManager 模板创建
- **给定**：需要生成的 DataTableManager
- **当**：使用模板系统生成代码
- **然后**：生成的代码与手动拼接的代码完全一致
- **验证**：`programmatic`

### AC-3：功能保持不变
- **给定**：完整的项目
- **当**：运行生成过程
- **然后**：生成的文件与之前完全一致，功能正常
- **验证**：`programmatic`

### AC-4：代码质量
- **给定**：重构后的代码
- **当**：检查代码质量
- **然后**：代码应符合 Rust 代码规范，有良好的注释
- **验证**：`human-judgment`
